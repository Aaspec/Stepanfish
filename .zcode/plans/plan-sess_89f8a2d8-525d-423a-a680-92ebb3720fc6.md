# Реализация задач 13, 15, 16, 17 (погода/время суток, ежедневные задания, достижения, дневник)

## Контекст
В игре «Тихий берег» (Python-сервер + SQLite + vanilla JS-фронтенд) уже есть 4 локации, магазин, справочник и морская рыбалка. Задач 13/15/16/17 в коде нет совсем — реализуем с нуля в существующей архитектуре: сервер авторитетен (экономика/улов в SQLite), клиент рисует и выбирает рыбу локально через `/api/config`. Автотесты по решению пользователя НЕ добавляем — только ручная проверка в браузере на изолированном стенде.

## Архитектура решений

**Время суток (13):** ускоренный игровой цикл — 4 части (утро→день→вечер→ночь) по 180 с, детерминированно из серверных часов: `floor(unix/180) % 4`. Без записи в БД, продолжается между сессиями.

**Погода (13):** хранится в БД (`world_state`): код + `weather_until`. При истечении сервер перекатывает заново (взвешенно: ясно .40 / дождь .25 / туман .20 / ветер .15) на 120–240 с. Влияние:
- дождь — общий вес поклёвки ×0.75 (клиентский `pick()`), но Форель клюёт только в дождь;
- туман — визуальный туманный слой поверх сцены, поплавок/рябь полупрозрачные;
- ветер — разброс дальности заброса ±12% и боковой снос поплавка, порывы на canvas.

**Активность рыб (13):** новые nullable-колонки `fish.times` и `fish.weather` (CSV кодов или NULL = всегда). Новые виды: **Налим** (только ночь; озеро/река; 1–7 кг; 400 ₽) и **Форель** (только дождь; река/пруд; 0.5–4 кг; 350 ₽). Лёгкие ограничения существующим: Плотва — утро/день, Окунь — утро/вечер, Тунец — день. Клиент фильтрует и взвешивает в `pick()`; если на наживку не клюёт никто — уже есть ветка «Тишина…».

**Ежедневные задания (15):** таблица `quest` (день, тип, цель, прогресс, награда, claimed). При обращении к `/api/state` — если на сегодня нет 3 заданий, генерируются случайно из каталога (~7 видов: «3 карася», «рыба > 2 кг», «2 рыбы на кукурузу», «5 любых рыб», «улов в море», «рыба на блесну», «2 рыбы на червя»). Награды: деньги (200–400 ₽) + запасы существующих приманок (по решению пользователя). Прогресс считает сервер в `post_catch` — для этого в `catch` добавляется `bait_id` (берётся из `active_cast`, клиент менять не нужно). Забор награды: POST `/api/quest/claim`.

**Достижения (16):** таблица `achievement(code, unlocked_at)`. Каталог: «Первый улов», «100 пойманных рыб», «Мастер моря» (поймать тунца), «Коллекционер» (все 12 видов). Проверка сервером после каждого улова; новые коды возвращаются в ответе `post_catch` и `/api/state` → клиент показывает toast-уведомление. Отдельная вкладка: открытые/неоткрытые + условия.

**Дневник (17):** агрегаты из существующей таблицы `catch` в `/api/state.diary`: всего рыб, самая тяжёлая (название+вес), счётчики по видам, открытые виды (пойманные хотя бы раз; неоткрытые — силуэт «?»). Автообновление: клиент уже вызывает `refresh()` после каждого улова.

## Изменения по файлам

**Новый `world.py`** (по образцу `sea.py`): константы (каталоги погод, частей суток, заданий, достижений), идемпотентная `migrate(c)` (ALTER catch.bait_id, fish.times/weather; CREATE world_state, quest, achievement; INSERT OR IGNORE налим/форель + fish_location/fish_bait), функции `day_part(now)`, `roll_weather(c, now)`, `ensure_quests(c, today)`, `check_achievements(c, ...)`, `diary(c)`.

**`db/schema.sql` / `db/seed.sql`:** те же колонки и таблицы для свежих установок; в seed — рыбы 11–12 с активностью, world_state-строка. Путь миграции (world.py) и путь свежей установки должны сходиться к одинаковой схеме.

**`server.py`:** `import world`, `world.migrate(c)` в `init_db`; `/api/config` дополняется каталогом погод/частей суток; `/api/state` — секции `world` (часть суток, погода, осталось секунд), `quests`, `achievements`, `diary`; `post_catch` — пишет `bait_id`, двигает прогресс заданий, проверяет достижения, возвращает `new_achievements`; новый POST `/api/quest/claim`.

**`static/index.html`:** кнопки навигации «Задания», «Достижения», «Дневник»; секции-вьюхи по образцу `#guide-view`; чип погоды/времени над сценой; контейнер toast-уведомлений.

**Новый `static/world.js`** (подключается до game.js): рендер трёх вкладок (карточки заданий с прогресс-барами и кнопкой «Получить награду», сетка достижений, статистика дневника), обновление чипа, toast.

**`static/game.js`:** `showGuide` обобщается в `showView(name)` для 5 вкладок; `pick()` — фильтр/веса по времени суток и погоде; разброс заброса при ветре (корректировка `bx` и боковой дрейф поплавка); оверлеи на canvas — затемнение/оттенки по времени суток, дождь (штрихи + круги по воде), туман (полупрозрачный слой поверх поплавка), порывы ветра; обработка `new_achievements` → toast.

**`static/guide.js`:** карточки рыб показывают активность («Только ночью», «Только в дождь», «Утро и вечер», «День»).

**`static/style.css`:** стили чипа, вкладок, карточек заданий/достижений/дневника, toast (по образцу существующих .guide-*/.location-* правил, с поддержкой dark-темы и мобильной сетки).

**`README.md`:** описание новых систем (без упоминания автотестов — их нет по решению пользователя).

## Проверка (только ручная, по решению пользователя)
1. `py -m unittest discover -s tests -v` — убедиться, что старые 5 тестов морской локации не сломались (их не меняем; новые не пишем).
2. Изолированный стенд `py -u .sharrowkin/scripts/preview_sea.py` (временная БД, реальный прогресс не трогается) + браузер:
   - чип «время суток · погода», оверлеи каждой погоды (форсируются через консоль стенда для наглядности);
   - заброс днём/ночью: состав клюющей рыбы меняется (налим ночью, форель в дождь);
   - прогресс задания после улова, кнопка «Получить награду», начисление денег/приманки;
   - toast «Первый улов» после первого улова, вкладка достижений;
   - дневник: счётчики, самая тяжёлая рыба, открытые виды — обновляются после улова;
   - справочник: метки активности новых видов; главное сохранение не затронуто.
